# Idea 18 — Physics-Informed ML with Thermodynamic Cycle Consistency

## Research question

ML stability predictors are trained on scattered mutations and often violate a basic
thermodynamic identity: **ΔΔG(X→Y) = −ΔΔG(Y→X)**, and more generally **ΔΔG around any closed
mutation cycle sums to zero** (ΔΔG(A→B) + ΔΔG(B→C) = ΔΔG(A→C)). Physics-informed machine
learning encodes such *symmetry/consistency laws* as constraints on the model. This project
builds a stability predictor whose predictions are **thermodynamically cycle-consistent by
construction** (or by a penalty term) and asks whether enforcing the law improves accuracy
and, more interestingly, *reduces error on extrapolation* to unseen mutation pairs.

The novelty: most people train a predictor to match labels; you train one that must ALSO
satisfy a physical identity the labels individually don't check. It's the biophysics analogue
of "equivariant" models in ML.

## Why this needs an SGE cluster

```
tasks = saturation-scan labels (thousands) + cycle-generation + training sweep
```

- Cycle consistency is *cheap to check* but *expensive to train against*: you need a large
  labeled mutation set (Idea-01 arrays) plus a large set of **mutation pairs/triples** whose
  consistency you penalize — combinatorial, generated by array tasks.
- The model itself (graph neural net or kernel model over mutation graphs) has a hyperparameter
  sweep that is a classic `qsub -t` grid (Idea-14).
- Enforcing consistency over a big mutation graph (a graph whose nodes are sequences, edges are
  single mutations) is where the compute goes; the cluster makes the graph big enough to matter.

## Data & tools

- **Labels:** FoldX saturation scan (Idea 01) or experimental DMS + ProTherm.
- **Model:** a graph/kernel predictor over the mutation graph (node = sequence, edge = single
  mutation). Enforce consistency two ways:
  - *Hard:* parameterize edge weights so any path between two nodes sums consistently
    (a "potential" on the graph → ΔΔG is a function of node potentials).
  - *Soft:* add a loss term penalizing cycle mismatch (standard approach; easier).
- **Solver:** PyTorch/geometric, or a small custom EM-like fitter. Free.
- **Validation:** hold-out DMS (Idea 05) + a physical sanity check: pick random 3-mutation
  cycles and measure residual imbalance vs a baseline model.

## Skill prerequisites

- Comfortable with the Idea-14 ML stack plus *some* physical reasoning (what a cycle identity
  means thermodynamically).
- Intermediate-advanced.

## Milestones

1. Build a mutation graph for one protein: nodes = 19 × N sequences, edges = single mutations.
2. Train a *baseline* predictor (no consistency constraint). Record test error + cycle-residual
   imbalance (how badly does it violate thermodynamics? — a great diagnostic plot).
3. Add the consistency penalty (soft version); retrain; compare test error and cycle residual.
4. (Stretch) build the *hard-consistent* version (node-potential parameterization); compare.
5. **Extrapolation test:** train on mutations at 60% of positions, test on the rest. Does
   consistency improve the hard extrapolation (positions the model never saw)?
6. Verdict: does enforcing a physical law help, hurt, or only add complexity?

## Deliverables

- **Cycle-imbalance diagnostic**: baseline vs constrained model, over thousands of random
  cycles (the "your predictor violates thermodynamics by this much" plot — memorable).
- Accuracy comparison (held-out Pearson/MAE), constrained vs baseline.
- A small paper-style "physics-informed ML for stability" write-up.

## Pitfalls

- **Hard consistency can flatten the model.** If every edge weight is a node-potential
  difference, you may lose genuine (non-path-independent) effects — real free energies are
  *not* exactly path-independent in finite sampling. The soft-penalty version is usually the
  honest one; report both.
- **Gauge freedom.** Node-potential parameterizations are defined up to an additive constant;
  fix the gauge (anchor WT = 0) or the fit is degenerate.
- **Don't fake consistency.** The penalty should shrink cycle residuals *in held-out cycles*,
  not just training cycles.
- **Label noise dominates.** If FoldX labels carry ±0.5 kcal/mol noise, enforcing cycle
  consistency may overfit the noise; use experimental DMS labels where possible.
- **Compute honesty.** This is a training project; the cluster's job is the label arrays and
  the sweep, not "one big GPU model." Scope accordingly.
